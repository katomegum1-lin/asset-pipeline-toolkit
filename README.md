# 资产管线工具包 · Asset Pipeline Toolkit

一套给 3D 美术用的**「建模端 → 引擎端」资产质量工具链**。
在模型进引擎**之前**把问题拦下来，减少返工。

> 支持 Blender 4.1+ / Maya 2022+ / UE5
> 纯节点与工具操作，**使用者不需要写任何代码**

## 它解决什么问题

做资产最烦的不是建模本身，而是「交上去被打回来」：

| 常见问题 | 建模阶段修 | 引擎里发现后修 |
|---|---|---|
| 非流形边 | 10 秒 | 重导 + 重做碰撞 + 重跑光照 |
| UV 重叠 | 2 分钟 | 重烘焙整张贴图 |
| 中文命名 | 10 秒 | 材质引用全断，逐个重连 |
| 缩放没应用 | 5 秒 | 尺寸全错，整体重来 |

**工具的作用**：把「交付后才发现」变成「交付前就报红」。

## 检查能力

两个版本检查项一一对应，保证 Blender 和 Maya 两条管线标准统一。

| 类别 | Blender | Maya | 说明 |
|---|:---:|:---:|---|
| 命名前缀 / 非法字符 | ✅ | ✅ | 中文、空格在 UE 里会被自动替换 |
| 三角面数超预算 | ✅ | ✅ | 按三角面算 |
| 非流形边 | ✅ | ✅ | 3 个以上面共享的边 |
| 重合面（Lamina） | ✅ | ✅ | z-fighting 与烘焙脏面 |
| 游离顶点 / 退化面 | ✅ | ✅ | |
| 法线整体反向 | ✅ | ✅ | 仅对封闭网格判断 |
| 无 UV / UV 重叠 / 越界 | ✅ | ✅ | 自实现重叠算法 |
| 缩放未应用 / 负缩放 | ✅ | ✅ | |
| 材质槽超限 / 空槽 | ✅ | ✅ | |
| **构造历史未清理** | — | ✅ | Maya 特有 |
| **开放网格自动跳过** | ✅ | ✅ | 避免布料类误报 |

**报告格式**：CSV（存档对比）+ HTML（发给别人看）+ 控制台（即时反馈）。

## 快速开始

### Blender

1. 打开 Blender → 顶部切到 **Scripting** 工作区
2. **Open** 选择 `blender/asset_lint.py` → **▶ Run Script**
3. 回 Layout，3D 视图按 **N** → 「资产检查」→「运行模型检查」

### Maya

1. **Windows → General Editors → Script Editor**
2. **File → Open Script** 选择 `maya/asset_lint_maya.py`
3. **Ctrl+A** 全选 → **Ctrl+Enter** 执行 → 窗口里点「运行检查」

详细步骤见各自目录下的 `使用说明.md`。

## 技术亮点

写在这里，方便面试时讲：

### 1. 问题在建模端拦，不在引擎端查
引擎端只能看到导入后的结果——此时命名可能已被自动替换、法线已被重算，
**原始问题被掩盖了**。建模端能看到真实数据。

### 2. 两个检测算法是自实现的

**UV 重叠**：没有直接用 Maya 的 `polyUVOverlap`。
实测「空间分离但 UV 坐标完全重合」的模型，该命令返回 `None` 漏检。
改为自实现：**空间哈希分桶**先筛候选，再用**边相交 + 顶点包含**做精确判定，
Blender 与 Maya 共用同一套标准。

**重合面**：`polyInfo laminaFaces` 依赖法线数据，API 构造的重合面会漏检。
改为按**顶点坐标集合**做指纹去重，只要能重合就抓得到。

### 3. 规则与逻辑分离
所有阈值集中在文件顶部「规则配置区」，换项目只改数字，不动检查代码。

### 4. 启发式检查会如实标注「疑似」
几何判断不是绝对真理（镜像 UV 是正常做法），
工具负责筛出需要人看的，**人来拍板**——而不是假装自己是真理。

### 5. 修法顺序写进了规范
「先几何 → 再 UV → 再法线变换 → 最后命名材质」不是随便排的。
顺序错了要返工。这条经验比任何一行代码都值钱。

## 02 一键导出管线

检查器管「模型合不合格」，导出器管「转换成引擎能吃的格式」。

| 自动化项 | Blender | Maya |
|---|:---:|:---:|
| 命名修正（非法字符 + 补前缀） | ✅ | ✅ |
| 应用/冻结变换 | ✅ | ✅ |
| 构造历史清理 | — | ✅ |
| 坐标轴转换（Z 上 / -Y 前） | ✅ | FBX 标准转换 |
| 单位换算（米 → 厘米） | ✅ | ✅ |
| `UCX_` 碰撞体自动带上 | ✅ | — |
| 原场景不被修改 | ✅ | ✅ |

两个平台都已用「脏模型」实测：命名修正、变换烘焙、尺寸正确、原场景未改，四项全过。

## 03 UE5 端导入与检查

建模端管「合不合格」，导出端管「转格式」，UE 端管「导入参数对不对」。

| 自动化项 | 支持 |
|---|:---:|
| 批量导入文件夹内所有 FBX | ✅ |
| 自动生成碰撞 / 合并网格 / 导入材质 | ✅ |
| 命名前缀检查 | ✅ |
| 引擎内实测面数、材质槽、空槽 | ✅ |
| LOD / 碰撞体缺失检查 | ✅ |
| 报告格式与建模端一致（CSV + HTML） | ✅ |

在 UE 5.8 实测：3 个 FBX 批量导入 → 4 个资产，检查出 4 条问题，全流程约 20 秒。

**用法**：UE 菜单 **Tools → Execute Python Script** 选择 `ue_import.py`，
或者按 README 里的步骤做成 EUW 按钮面板。

## 完整链路

```
建模端（Blender / Maya）
   ├─ 检查器  → 拦拓扑 / UV / 命名问题
   └─ 导出器  → 修正命名、烘焙变换、导出 FBX
        ↓
UE5 端
   └─ 导入器  → 批量导入 + 查导入参数问题
```
